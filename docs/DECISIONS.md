# Decisions (ADRs — append, never rewrite history)

- **ADR-001 — gnu + zig linker, no MSVC.** No admin → no VS Build Tools. `stable-x86_64-pc-windows-gnu` + zig as linker/`CC` (`.cargo/config.toml`). Revisit if a crate needs MSVC-only asm.
- **ADR-002 — Balanced 9/10/9 default shards** (0–8/9–18/19–27). 16/8/4 kept only as heterogeneity fit. (research/03 §7)
- **ADR-003 — Optimistic commit, not per-token 2PC.** Piggyback `COMMIT(pos-1)`, abort via `TRUNCATE(pos)`. (research/05 §3)
- **ADR-004 — Single-device fast path before pipeline.** Pipeline pays `(P-1)` hop tax; 0.6B fits one node. (review §1)
- **ADR-005 — Android TCP+TLS first, QUIC later** behind `InferenceTransport`. (research/04 §4)
- **ADR-006 — KV block 16, recompute-preempt.** 32 only if p50>1K and preemption<5%. Checkpoint K=64–128. (research/05)
- **ADR-007 — Curated catalog only.** One pinned publisher per quant (unsloth). No arbitrary GGUF URLs in MVP.
- **ADR-008 — FGS type `connectedDevice`.** `dataSync` capped 6h/24h on API 35+. Wake lock only during compute. (research/04 §3)
- **ADR-009 — Token-level cross-ISA contract.** Accept `max|Δlogit|<0.5` + top-1 >99.5%; never chase bitwise ARM==x86.
- **ADR-010 — Layer-execution spike opens Phase 3.** llama.cpp public API has no layer-range run; options ranked RPC-sidecar > custom shard forwarder > sys-fork > candle. Data-parallel fallback ships value regardless.
- **ADR-011 — Minimal tooling policy.** 2 remote MCPs (context7, gh_grep) + reputable project-local skills only; no low-trust binaries; heavy tools enabled per-task. Rejections logged in `docs/MCP_SKILLS.md`.
- **ADR-012 — WinLibs MinGW UCRT over zig-as-linker.** Bare `zig` as cargo linker chokes on rustc's `-fno-use-linker-plugin`, and `windows-sys` needs real `dlltool.exe`. User-space WinLibs gives gcc/ld/dlltool/ar with no admin.
- **ADR-013 — llama-cpp-2 pinned `=0.1.156`.** Only maintained binding in 2026; CPU-only default features; no CUDA/Vulkan on MinGW.
- **ADR-014 — Model weights dir `%LOCALAPPDATA%\dllm\models\` outside repo.** Fallback `./models/` if `LOCALAPPDATA` unset; keeps weights out of git.
- **ADR-015 — Pull = single-file HF download + Range resume + size verify (+ sha when known.** `model_dir()` + `.part` sidecar, `Range: bytes={have}-`, progress log, `bytes` size check, sha256 check skipped while catalog is `TODO-SHA256`; `files[]` stay byte-ranges of same URL until Phase 3 splitter.
- **ADR-016 — Q4_K_M unsloth ~397MB vs Q8 official ~639MB.** Q4 default for LAN fit; Q8 kept as quality option (one pinned publisher per quant per ADR-007).
- **ADR-017 — sha256 not published by HF (verify via download + sidecar).** No upstream hash to pin; verify byte-size + hash-on-download, record observed hash in `.sha256` sidecar next to weights for audit.
- **ADR-018 — Quinn mTLS with TOFU fingerprints.** No CA: self-signed certs, pin `sha256(cert_der)` hex both ways; server `allowed_peers` set + client `expected_fingerprint` strict after first pairing (`crates/dllm-net/src/transport.rs`).
- **ADR-019 — Stream priorities Control(20) > Ack(10) > Activation(0).** Plan/commit pre-empts bulk tensors; ACKs tiny + latency-sensitive (`StreamKind::priority`, `open_stream` sets `set_priority`, 1-byte kind tag).
- **ADR-020 — Frame queue cap 4 + QUIC flow-control backpressure.** `frame_channel` cap 4; `spawn_frame_recv_loop` parks on full queue so a slow consumer stalls the peer via QUIC flow-control instead of growing memory; 8 MiB frame cap checked before alloc.
- **ADR-021 — Calibration planner minimizing max stage time.** `plan_layers` assigns contiguous ranges minimizing max per-stage time (compute share + one activation hop); exhaustive search (≤5 stages) with balanced/edge-symmetric tie-breaks, greedy fallback beyond 5M compositions.
- **ADR-022 — QUIC worker port 8443.** `server()` binds `0.0.0.0:8443`, ALPN `dllm/1`; TXT `quic_port` override stays for discovery; loopback drill `pipe_pair` uses 127.0.0.1:8443.
- **ADR-023 — Event-log TTL 24 h + WAL checkpoint after prune.** Retention default `DEFAULT_EVENT_TTL_SECS = 24*60*60`; `DLLM_EVENT_TTL_SECS` env override wins over the call parameter. Maintenance loop (60 s cadence): `prune_older_than(now-TTL)` then `Store::checkpoint` → `PRAGMA wal_checkpoint(TRUNCATE)` so the WAL stays bounded (`crates/dllm-serve/src/lib.rs`, `crates/dllm-store/src/lib.rs`; wired in `run_serve`).
- **ADR-024 — `/api/stats` telemetry surface.** `GET /api/stats` returns `{uptime_s, engine(llama|mock), sessions, events, node_id}` — operational/telemetry only, no chat content. Tiny inline reads are an MVP exception; production moves them to `spawn_blocking` (same blocking contract as the SSE writer path).
- **ADR-025 — JNI worker ABI locked to 3 symbols.** `LlamaBridge.loadModel / inferChunk / free` (`apps/android/app/src/main/cpp/worker.cpp`) is the stable ABI between the app and the bundled real llama.cpp `.so`; decode + sampler chain live inside `inferChunk`. Adding/removing/renaming symbols requires a new ADR.
- **ADR-026 — Multi-candidate LAN IPs, 192.168-first ranking.** Single-IP `lan_ipv4` via the outbound-route trick misfires on multi-homed hosts (VPN/PPP `/32` like `172.16.0.2` beats WiFi `192.168.x`). `lan_candidates()` enumerates via hostname resolution + outbound trick, filters non-routable, ranks `192.168 > 10 > 172.16/12 > other`; `lan_ipv4()` = best pick, `GET /api/pairing-uri` + `dllm id` expose all candidates. No new deps (std + existing `hostname`). Joiner tries candidates in order; manual override always available.
- **ADR-027 — Stable ANDROID_ID identity + device hard-delete with self-guard.** Android `node_id` is a deterministic UUID from `ANDROID_ID` (`UUID.nameUUIDFromBytes("dllm-mesh:"+androidId)`, `IdentityStore.ensureNodeId`), stable across reinstalls (reset only on factory reset; random-UUID fallback when ANDROID_ID is missing/broken `9774d56d682e549c`); pairing/scan/manual/nearby flows never rotate it, and a "Use existing ID" UI (`IdentityStore.setNodeId`, Devices + Pairing screens) adopts a prior id so one heartbeat reuses the old row instead of minting a dupe; all heartbeat senders share one builder (`buildHeartbeatBody`: device_id/role/permissions/device_name). Server `DELETE /v1/devices/{id}` (`Store::delete_device` + `dllm-serve::delete_device`) hard-deletes the registry row for drill junk / stale dupes (200 `{ok:true,id}` / 404 unknown, no broadcast); refuses the self coordinator row with 400 (`id == node.node_id`, never orphan the mesh); a later heartbeat recreates the row as `paired` via `upsert_device`. Ops: `DELETE drill-pixel-8` via the new route.
- **ADR-028 — Mesh allow-list is a projection of the device registry (TOFU on `cert_fp`), and a bind failure never kills HTTP.** `MeshState` (`crates/dllm-serve/src/mesh.rs`) holds the live links; admission is not a second allow-list file: `refresh_allow_list` admits exactly the registry rows with `status == "paired"` **and** a non-null, non-empty `cert_fp`, mapping lowercase fingerprint → `device_id`. An HTTP-heartbeat-only device is deliberately **not** mesh-eligible: heartbeat is a self-declared liveness ping over a channel with no crypto, so admitting on it would let any process that can reach :8080 claim a mesh slot; a device must pair (exchange a certificate + fingerprint) before it can hold a QUIC link, which keeps ADR-018's TOFU pin meaningful because the pin is established at pairing time, not at first heartbeat. Consequences we accepted: `allowed_peer_count` (not link count) is what `/v1/mesh` and `/api/stats` report, so an unpaired device is honestly "not eligible" rather than "refused". Revocation is an *authorization* event, not a bookkeeping one, so `tick`/revocation removes the peer's live `PeerLink` and closes the connection — a revoked device must not keep streaming on a link it opened while paired. `spawn_mesh_server` binds the UDP socket **synchronously** and, on failure, logs and returns an already-finished `JoinHandle` instead of `unwrap`/`expect`: single-device chat (ADR-004 fast path) is the product, so a busy 8443 must degrade to "no mesh" (`quic_port: 0`, `endpoint: "unbound"`, HTTP untouched) rather than take down the coordinator. Accept loop awaits each `Incoming` so the TLS handshake — and therefore the allow-list check — actually executes; dropping the future would have admitted unauthenticated sockets silently. `rtt_us` stays `null` until a real sample exists (rolling median over `MESH_RTT_WINDOW`), never synthesized. Ops: `GET /v1/mesh` is the honest window onto all of this.
- **ADR-029 — Hand-rolled fixed-width little-endian wire format, and a separate `ACK1` magic namespace.** `crates/dllm-net/src/lib.rs` encodes `ActivationFrame` v1 exactly as `contracts/activation-frame.md` specifies: `FRAME_HEADER_LEN = 40`, `MAX_FRAME_BYTES = 8 MiB`, `MAX_PAYLOAD_BYTES`, `MAX_STAGES = 5`, `magic` as **field 0 at offset 0** (not a prefix outside the body), `payload_length` as an explicit `u32` at offset 36, total always `40 + payload_length`; `decode_frame_header`/`encode_frame_header`/`FrameHeader` are exposed so a peer can read the header without touching the payload. Why not postcard (the previous implementation): the Android JNI forwarder is not Rust, so the format must be encodable byte-for-byte from the contract table with nothing but `ByteBuffer.putLong/putInt/put`. A serialization crate makes the wire a *Rust implementation detail* — and that is exactly what happened: postcard varint encoding with `magic` outside the struct silently diverged from the documented contract, so any contract-conformant non-Rust peer would have misparsed **every** frame while the Rust round-trip tests stayed green. Same class of bug: ACKs previously shared the `DLLM1` magic with activation frames, so an ACK arriving on a data stream was indistinguishable from a frame; ACKs now live in their own namespace — `ACK_MAGIC = "ACK1"`, `ACK_HEADER_LEN = 8`, `MAX_ACK_BYTES = 256`, wire form `ACK1 || u32-LE len || {"ack":"COMPUTED","pos":3,"token":42}` with `UnknownAck`/`AckTooLarge`/`AckJson` errors. Decode validates **cheap-before-semantic**: truncated → magic → 8 MiB cap → stage range → `target_stage == source_stage + 1` (`StageMismatch`) → known `tensor_format` → `payload_length` vs actual trailing bytes, so a corrupt/hostile peer cannot make the receiver allocate or reason about a nonsense frame first; new `NetError` variants `Truncated`, `StageMismatch`, `StageOutOfRange`, `UnknownTensorFormat`, `AckTooLarge`, `UnknownAck`, `AckJson` make each rejection nameable instead of collapsing into a generic parse error. `tensor_format::U8_BYTES` was renamed `tensor_format::RAW` (255) and documented as reserved/diagnostics-only: it was never a real activation format and having it in the enum invited peers to send garbage as data. Tests pin exact offsets (`crates/dllm-serve/tests/frame_roundtrip.rs`) precisely so the table in the contract is the thing that breaks first when the format drifts.
- **ADR-030 — The single-device plan is computed by the real planner, and unknown timings are explicit nulls.** `GET /v1/plan` and `GET /v1/usage`'s `plan` mirror used to short-circuit: whenever `pipeline_candidates()` returned ≤ 1 device they returned a hardcoded `{plan_id: 1, stages:[{device_id: self, layer_start: 0, layer_end: 27}]}`. Both now route through `dllm_core::plan_layers(TOTAL_LAYERS, &specs)` — ADR-021's exhaustive search, balanced/edge-symmetric tie-breaks and all — so `plan_id` is the planner's real membership hash (identical inputs → identical id; adding a candidate changes the id) and one code path serves every arity instead of a fake branch that would have masked a broken planner (verified live: `plan_id 6747772075584906592` with a single self stage). `latency_ms` (per stage) and `bottleneck` are emitted as **explicit `null` keys**, not omitted and not invented: nothing measures per-stage latency over the mesh yet because no pipeline runs (ADR-028/E4 in `docs/CONNECTIONS.md`), and a key that is simply missing reads as "the server forgot" while an explicit null reads as "measured: nothing". Clients (`apps/web` Distribution tab, Android) must therefore render "not measured yet" rather than `0`/`—`; `note` (`single-device fast path` / `multi-device plan via plan_layers`) is informational and never load-bearing.

- **ADR-032 � Layers execute across devices via a C++ shim over ggml-rpc, loaded at runtime.** `llama-cpp-2` vendors a llama.cpp with no `ggml/src/ggml-rpc/` and its bindgen never includes `ggml-rpc.h`, so zero `ggml_rpc*` symbols are reachable from Rust; ggml backend registration is also C++-vtable-bound, so Rust cannot fabricate a remote backend either. `native/` therefore owns one C++ translation unit linking llama.cpp + ggml-rpc behind the plain C ABI in `native/include/dllm_shim.h`, and `crates/dllm-shim` binds it. The DLL is **loaded at runtime** (`DLLM_SHIM_DLL` or a build-relative probe), not link-time, so a machine without the prebuilt shim still boots and serves single-device chat via `LlamaEngine` -- a missing optional native artifact must never be able to stop the coordinator from starting. ABI version is checked before use. Export table is generated from the header by CMake so it cannot drift. Two build-time facts worth recording: MinGW emits `ggml-rpc.a`, **not** `libggml-rpc.a`, on `win32-mingw`; and `-fvisibility=hidden` is a **no-op in PE/COFF**, so the shim would otherwise export all 3376 llama/ggml/CRT symbols and risk a duplicate-`llama_decode` bind against the copy `llama-cpp-2` links statically -- hence the generated `.def`. tensor_split weights are derived from `plan_layers` stage layer counts, RPC endpoints are registered in stage order so `layer_owner` indices align with stage indices, and duplicate endpoints are dropped (a double add would duplicate ggml device slots). Requested vs measured placement are both surfaced and never silently reconciled. **Trust model: ggml-rpc is plaintext TCP with no authentication.** Upstream warns "Never expose the RPC server to an open network!". Acceptable only because membership is gated on the paired-device registry on a trusted LAN; it is NOT a substitute for the QUIC/mTLS edge in E4. Verified live on loopback: 28 layers split 12/16 across two processes, `graph splits = 2`, 13 tokens streamed at 16.3 tok/s with requested 11/17 and measured 12/16.
- **ADR-033 � The phone hosts an RPC server over JNI; the ADR-025 ABI is extended, not replaced.** `GGML_RPC=ON` is now mandatory in `build-llama-ndk.ps1` and the script hard-fails if `libggml-rpc.a` is absent, because without it `ggml_backend_rpc_start_server` does not exist and the phone silently cannot host layers at all. `worker.cpp` gains `shimInit`/`shimFree`/`shimAbiVersion`/`shimLastError`/`rpcServeStart`/`rpcServeStop`/`rpcServing`/`rpcProtocolVersion` alongside the existing three ADR-025 symbols, which are untouched. `dllm_shim_rpc_serve` blocks and the ABI has no stop path (ggml's `start_server` returns void), so the service owns the threading and stop is cooperative. Same plaintext-TCP caveat as ADR-032 applies to the phone.
