## 2026-10-04 — Contract-conformant frame codec + bound QUIC mesh + computed plan (correctness pass)

- Wire format (`crates/dllm-net/src/lib.rs`): the codec was postcard varints with `magic` as a prefix *outside* the struct body, while `contracts/activation-frame.md` has specified a fixed-width little-endian layout (`magic` at offset 0, explicit `payload_length` u32 at 36) since Phase 0 — any contract-conformant non-Rust peer (the Android JNI forwarder) would have misparsed **every** frame, and Rust round-trip tests could not see it. Hand-rolled fixed-width LE now: `FRAME_HEADER_LEN = 40`, `MAX_FRAME_BYTES = 8 MiB`, `MAX_PAYLOAD_BYTES`, `MAX_STAGES = 5`, plus `decode_frame_header`/`encode_frame_header`/`FrameHeader`. Validation is cheap-before-semantic (truncated → magic → size cap → stage range → adjacency → `tensor_format` → length match) with new `NetError` variants `Truncated`, `StageMismatch`, `StageOutOfRange`, `UnknownTensorFormat`, `AckTooLarge`, `UnknownAck`, `AckJson`. ACKs no longer share the `DLLM1` magic with activation frames — their own namespace: `ACK1 || u32-LE len || {"ack":"COMPUTED","pos":3,"token":42}` (`ACK_HEADER_LEN = 8`, `MAX_ACK_BYTES = 256`). `tensor_format::U8_BYTES` renamed `tensor_format::RAW` (255) and documented reserved/diagnostics-only. ADR-029.
- QUIC mesh (`crates/dllm-serve/src/mesh.rs`, new): `dllm serve` used to mint a persistent certificate, advertise its fingerprint over mDNS and in the pairing URI, then discard it — nothing ever bound 8443 or opened a QUIC socket, which made the "DONE headless" E4 row in `CONNECTIONS.md` false. `spawn_mesh_server(identity, port, store, mesh)` now binds `0.0.0.0:8443` **synchronously**; on bind failure it logs and returns a finished stub task so HTTP serving always continues (single-device chat must not require the mesh); each `Incoming` is awaited so the TLS handshake — and therefore the allow-list check — actually runs; a monitor tick reaps closed links and refreshes `last_seen`. `MeshState` keys live links by certificate fingerprint (resolved `device_id`, `quinn::Connection`, connected/last-seen timestamps, bounded rolling RTT window `MESH_RTT_WINDOW` = median), and `rtt_us` stays `null` until a real sample exists — never synthesized. ADR-028.
- Allow-list = TOFU projection of the device registry: admitted iff `status == "paired"` **and** a non-null non-empty `cert_fp`. A device that has only sent an HTTP heartbeat is deliberately not mesh-eligible (heartbeat carries no crypto), so pairing must come first; revoking a device tears its live link down.
- Observability: new `GET /v1/mesh` → `{quic_port, endpoint, peers[], allowed_peer_count}`; peer entries carry `device_id`, nullable `device_name`, `fingerprint`, nullable `rtt_us`, `connected`, `connected_since_ms`, `last_seen_ms`. `/api/stats` gains `mesh{peers_connected, allowed_peers}`. Verified live: `{"allowed_peer_count":1,"endpoint":"0.0.0.0:8443","peers":[],"quic_port":8443}`.
- Plan (`GET /v1/plan`, `GET /v1/usage`): the ≤1-device path returned a hardcoded `{plan_id: 1, stages:[{device_id: self, layer_start: 0, layer_end: 27}]}`; both are now routed through the real `dllm_core::plan_layers(TOTAL_LAYERS, &specs)`, so `plan_id` is the planner's membership hash and one code path serves every arity. `latency_ms` and `bottleneck` are emitted as explicit `null` keys — omitted would read as "the server forgot", invented would be a lie; nothing measures stage time yet. Verified live: `{"bottleneck":null,"note":"single-device fast path","plan_id":6747772075584906592,"stages":[{"device_id":"dllm-7651a03dca4d","latency_ms":null,"layer_end":27,"layer_start":0,"stage":0}]}`. ADR-030.
- Web (`apps/web`): the 2069-line `App.tsx` is now 200 lines over a real module layout (`api/{types,http,parse}.ts`, `lib/{layers,messages,storage,format,strip,palette}.ts`, `state/{useChat,useDevices,useDistribution,useConnection,useUsageTab}.ts`, `tabs/*`, memoized `components/*`). Tabs are Chat · Devices · Distribution · Models · Usage — **Networks tab removed**. The new Devices tab wires `/v1/devices`, `/api/pairing-uri`, approve/revoke/delete (endpoints that already existed server-side and that the web app previously called *none* of); Distribution renders contiguous per-device layer runs, stage latency, bottleneck, per-device CPU/MEM with honest "not measured yet" states.
